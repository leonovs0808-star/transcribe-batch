# Инструкция для ИИ-агента: установить transcribe-batch

Ты помогаешь пользователю поставить **transcribe-batch** — навык, который расшифровывает
аудио/видео в текст и размечает разговоры по спикерам. Работает и с файлами на
компьютере, и со ссылками (YouTube, ВК Видео, Рутуб, Кинескоп, Дзен, Vimeo,
Яндекс.Диск, Google Drive, прямая ссылка на файл). Пользователь, скорее всего, не
программист — веди его пошагово, без жаргона, объясняй что и куда нажать/вставить.

Движок по умолчанию — **Deepgram**: он работает из любой страны, включая Россию, и один
умеет различать голоса. Ключ нужен ровно один, его и получаем на шаге 3. Groq — опция
для тех, кто за пределами России и хочет бесплатно; предлагай его только если
пользователь сам об этом заговорил.

Инструкция одна на все системы и на всех агентов. **Ничего не спрашивай про операционную
систему и про то, кто ты — определи сам** по шагу 0, и дальше выдавай пользователю только
те команды, которые подходят именно его случаю. Не показывай ему варианты для чужих систем.

## Железное правило: настройки компьютера пользователя ты не трогаешь

НИКОГДА не проси пользователя менять настройки его VPN, прокси, Clash, файрвола или
системной сети — не переключать «Правила/Глобальный», не менять порты, не отключать
защиту. Это его рабочая инфраструктура, через неё у него может идти что-то ещё, и
ломать её ради одной расшифровки нельзя.

Это относится и к расшифровке: движок по умолчанию (Deepgram) работает напрямую
отовсюду, поэтому повода трогать сеть пользователя нет в принципе. Если пользователь
сам выбрал Groq и получил `HTTP 403` — это значит только одно: Groq не обслуживает его
страну. Правильное решение — вернуться на Deepgram, а не чинить его VPN.

## Шаг 0. Определись сам (не спрашивая пользователя)

**Сначала убедись, что вы на одной машине.** Ты ставишь скрипт туда, где выполняешь
команды. Если ты работаешь на удалённом сервере, в контейнере или в WSL, а человек сидит
за своим Маком или Windows — это РАЗНЫЕ компьютеры, и скрипт встанет не туда, где лежат
его записи. Проверь это ДО установки, но спрашивай по-человечески, без слов «сервер», «контейнер»
и «WSL». Рабочая формулировка: «назови любую папку с твоими записями — проверю, вижу
ли я её». Дал путь, а ты его не находишь — значит вы на разных машинах. Тогда скажи
прямо: «я работаю не на твоём компьютере, твоих файлов отсюда не видно» — и разберитесь,
ставим ли на его машину или он будет складывать записи туда, где работаешь ты. Молча
ставить «куда получится» нельзя: человек потом не найдёт ни скрипт, ни расшифровки.

Это единственное исключение из правила «ничего не спрашивай» — здесь вопрос дешевле,
чем установка не на ту машину.

**Какая система.** Если у тебя есть доступ к терминалу — просто выполни:

```bash
python3 -m platform
```

(Форму `python3 -c "…"` не используй: во многих агентных средах она запрещена политикой
безопасности и вернёт отказ, а не ответ. Если `python3 -m platform` недоступна — подойдёт
`uname -s` на macOS/Linux и `echo $env:OS` в PowerShell.)

`Darwin` = macOS, `Linux` = Linux, `Windows` = Windows. Если команда не нашлась — почти
наверняка Windows, там интерпретатор называется `python`, проверь `python --version`.
Если доступа к терминалу нет — спроси у пользователя одним коротким вопросом
(«у тебя Mac или Windows?»), не устраивая опрос.

Дальше по всей инструкции:
- macOS / Linux — команда `python3`, терминал bash/zsh
- Windows — команда `python`, терминал PowerShell

**Кто ты.** От этого зависит только одно — куда класть папку навыка:

| Ты | Папка навыков |
|----|---------------|
| Claude Code | `~/.claude/skills/transcribe-batch` |
| Codex | `~/.codex/skills/transcribe-batch` |
| Другой агент со своей папкой навыков | его папка навыков |
| Обычный чат в браузере (ChatGPT/Claude без доступа к терминалу) | любая обычная папка, например `~/transcribe-batch` — навыка не будет, останется скрипт, который запускают командой |

На Windows `~` в PowerShell не всегда раскрывается — пиши `$env:USERPROFILE\.claude\skills\transcribe-batch`.

Если ты в браузере без доступа к компьютеру пользователя — диктуй команды по одной, жди,
что он скопирует их в свой терминал и пришлёт вывод обратно. Ни ChatGPT, ни Claude в
браузере не видят файлы на его компьютере и ничего там сами не откроют.

**Как объяснить пользователю, что такое терминал:**
macOS — приложение «Терминал» (Cmd+Space → «Терминал»).
Windows — «PowerShell» (Пуск → набрать «PowerShell»).

## Шаг 1. Проверь зависимости

macOS / Linux:
```bash
python3 --version
ffmpeg -version
git --version
```

Windows (PowerShell):
```powershell
python --version
ffmpeg -version
git --version
```

Нужен Python **3.8 или новее**.

Один pip-пакет ставится по желанию — **yt-dlp**, он нужен только для ссылок на YouTube
и другие видеохостинги. Спроси пользователя, будет ли он давать такие ссылки. Будет —
поставь сразу, это одна команда (на Windows `python` вместо `python3`):

```bash
python3 -m pip install -U yt-dlp
```

Ставишь его ты, не человек — прав администратора тут не нужно.

**Если ответит `error: externally-managed-environment`** — это не поломка, так устроены
свежие Ubuntu/Debian и Python из Homebrew: они запрещают ставить пакеты в системный
питон. Обходится одной из команд, пробуй по порядку:

```bash
python3 -m pip install -U --break-system-packages yt-dlp
pipx install yt-dlp        # если в системе есть pipx
sudo apt install yt-dlp    # на Debian/Ubuntu; пароль вводит человек, не ты
```

Для файлов, папок, Яндекс.Диска, Google Drive и прямых ссылок он не нужен — без него
всё это работает.

- **Python отсутствует** — https://www.python.org/downloads/ (macOS/Windows) или
  `sudo apt install python3` (Linux). На Windows при установке обязательно отметить
  галочку «Add python.exe to PATH», иначе команда не найдётся. Если `python` открывает
  Microsoft Store вместо версии — это стандартная заглушка Windows, помогает та же
  переустановка с галочкой.
- **ffmpeg отсутствует**:
  - macOS: `brew install ffmpeg` (нет Homebrew — сначала `/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"`)
  - Linux: `sudo apt install ffmpeg`
  - Windows: `winget install Gyan.FFmpeg` (или `choco install ffmpeg`, или вручную
    с https://www.gyan.dev/ffmpeg/builds/ — сборка essentials, распаковать, папку `bin`
    добавить в PATH). После установки терминал надо открыть заново.
- **git отсутствует** — macOS: `xcode-select --install`; Windows: https://git-scm.com/download/win

**Кто ставит недостающее — важный момент, не пропусти его.** Команды установки ты
выдаёшь, но выполнить их сам можешь не всегда:

- `sudo apt install ffmpeg` **потребует пароль пользователя**. Пароль у тебя просить
  нельзя и вводить за него тоже. Такую команду отдай ему целиком и попроси выполнить
  у себя, а потом прислать вывод.
- Установка Homebrew на macOS идёт строкой вида `/bin/bash -c "$(curl -fsSL …)"`.
  Во многих агентных средах `curl` запрещён политикой — у тебя она может просто не
  запуститься. Тогда не изобретай обход: отдай строку человеку, пусть выполнит сам.
- На Windows `winget install Gyan.FFmpeg` обычно проходит без пароля, но требует
  перезапуска терминала — а для тебя это означает перезапуск твоей сессии, а не просто
  «открой новое окно». Предупреди его, что после установки ffmpeg вы, возможно,
  начнёте заново, и это нормально.

Не продолжай, пока версия Python и ffmpeg не печатаются без ошибок.

## Шаг 2. Скачай проект

Подставь папку из таблицы шага 0. Пример для Claude Code на macOS/Linux:

```bash
git clone https://github.com/leonovs0808-star/transcribe-batch.git ~/.claude/skills/transcribe-batch
cd ~/.claude/skills/transcribe-batch
cp .env.example .env
```

Пример для Codex на Windows (PowerShell):

```powershell
git clone https://github.com/leonovs0808-star/transcribe-batch.git $env:USERPROFILE\.codex\skills\transcribe-batch
cd $env:USERPROFILE\.codex\skills\transcribe-batch
copy .env.example .env
```

**Пиши команды абсолютными путями.** Многие агентные среды сбрасывают рабочую папку
между командами, и связка «`cd` в одной команде — относительный путь в следующей»
разваливается молча. Это касается и `cp .env.example .env`: указывай полный путь.

**Папка уже существует** (вторая попытка после неудачной первой) — `git clone` упадёт
с «destination path already exists». Не придумывай новое имя: зайди в эту папку и
выполни `git pull`, либо удали её и клонируй заново, предварительно спросив человека,
нет ли там его файлов.

Если git не ставится или пользователь не готов с ним разбираться — альтернатива: скачать
ZIP со страницы https://github.com/leonovs0808-star/transcribe-batch (зелёная кнопка
**Code → Download ZIP**), распаковать. Скачивание и распаковку делает человек, дальше
работаешь ты. Папка после распаковки называется `transcribe-batch-master`, а не
`transcribe-batch` — **переименуй её в `transcribe-batch`**, иначе агент не опознает
навык: имя папки должно совпадать с `name:` внутри `SKILL.md`. Затем создай `.env`
абсолютным путём — без него следующий шаг сломается.

## Шаг 3. Ключ Deepgram — это делает ЧЕЛОВЕК, не ты

**Сразу скажи пользователю, что этот шаг — его.** Тебе нужен браузер и его почта,
у тебя их нет. Не делай вид, что можешь получить ключ сам, и не проси его «дать доступ
к аккаунту» — ничего такого не нужно.

Продиктуй ему по шагам, дословно примерно так:

1. Открыть https://console.deepgram.com и нажать **Sign Up** — можно войти через Google
   или GitHub. **Карту не спрашивают.** На счёт сразу кладут $200, они не сгорают —
   это примерно 700 часов расшифровки. Проект создаётся автоматически при регистрации,
   заводить его руками не надо.
2. В консоли открыть **Settings** (шестерёнка/пункт настроек проекта) → раздел
   **API Keys** → кнопка **Create a New API Key**.
3. Имя — любое, например `transcribe`. Права (Permissions) — **Member** достаточно.
   Срок (Expiration) можно оставить бессрочным.
4. Ключ показывается **ОДИН раз** — длинная строка из букв и цифр. Скопировать целиком,
   без пробелов по краям. Закрыл окно, не скопировав — не страшно, просто создать новый
   тем же путём.

**Если он говорит, что не видит такого пункта** — не настаивай на формулировках выше
и не гадай. Попроси описать, что он видит на экране, и веди от этого: интерфейс
периодически меняется, а твоя задача — довести до ключа, а не защитить инструкцию.

### Куда девать ключ — три варианта, выбирает человек

Ключ — это деньги на его счету и доступ к его аккаунту. Скажи об этом прямо, покажи все
три варианта и дай выбрать. **Сказал «делай как лучше» — бери вариант Б:** он быстрый
и при этом ключ не попадает в переписку.

Во всех трёх вариантах запись делает сама программа командой `--set-key`. Своих строк
на питоне для этого не пиши: самодельная строка считает путь от текущей папки, и при
забытом `cd` ключ уходит в чужой `.env` — молча, с бодрым «ОК» в ответ. `--set-key`
пишет в `.env` рядом со скриптом, промахнуться некуда, и сразу проверяет ключ у сервиса.

**Вариант А — он присылает ключ тебе в чат, ты вписываешь.** Самый быстрый.
Честно предупреди: ключ останется в истории вашей переписки и уйдёт на серверы того
сервиса, через который ты работаешь.

```bash
python3 transcribe.py --set-key deepgram ВСТАВЬ_КЛЮЧ_СЮДА
```

**Вариант Б — ключ не проходит через чат.** Дай ему эту команду, он выполнит её сам:
программа спросит ключ вводом, он вставит его в своём терминале. Ни ты, ни переписка
ключа не увидят.

```bash
python3 transcribe.py --set-key deepgram
```

**Вариант В — руками в файле**, если терминал ему неприятен. `.env` — скрытый файл:
- macOS Finder: в папке проекта нажать **Cmd+Shift+.** (точка).
- Windows Проводник: вкладка **Вид** → включить **Скрытые элементы**.

Открыть `.env` в TextEdit/Блокноте, заменить плейсхолдер на реальный ключ:
```
DEEPGRAM_API_KEY=реальный_ключ_пользователя
```
и сохранить **как обычный текст**, не меняя имя файла (TextEdit и Блокнот любят
дописать `.txt` — проследи, чтобы файл остался именно `.env`).

Любой из трёх вариантов заканчивается одинаково: команда (или `--check`) говорит
`есть, ключ принят` — значит готово. Говорит `НЕ ПРИНЯЛ (401)` — ключ скопирован
с опечаткой или обрезан, пусть создаст новый, чинить старый не надо.

### Что тебе самому нельзя делать с ключом

- **Не повторяй ключ в чате** — ни «записал ключ abc123», ни в подтверждении, ни в
  пересказе команды. Одного эха достаточно, чтобы ключ осел в переписке даже в варианте Б.
- **Не сохраняй его в свою память, заметки или файлы проекта.** Ему место только в `.env`.
- **Не коммить `.env` в git** — он уже закрыт в `.gitignore` репозитория, просто не
  выноси его оттуда.

Скажи человеку одну вещь про утечку, коротко, без запугивания: если ключ где-то
засветился (переслал не туда, попал в скриншот) — зайти в ту же консоль Deepgram,
удалить этот ключ и создать новый. Старый сразу перестанет работать.

### Сколько это стоит, когда $200 кончатся

Спросит — отвечай честно: дальше оплата по факту, примерно $0,0043 за минуту записи
(около 26 центов за час). Счёт сам по себе не спишется: чтобы платить дальше, надо
отдельно привязать карту. Не привяжет — сервис просто перестанет принимать запросы,
никакого долга не появится.

## Шаг 3-бис. Только если пользователь за пределами России и хочет бесплатно

Groq даёт распознавание бесплатно, но не обслуживает Россию (там `HTTP 403`) и не умеет
различать голоса. Сам это не предлагай — только если пользователь спросил про бесплатный
вариант и живёт там, где Groq работает.

1. https://console.groq.com → **Sign In** → **API Keys** → **Create API Key**.
2. Вписать в тот же `.env` строкой `GROQ_API_KEY=gsk_...` — тем же способом, что выше.
3. Запускать с флагом:
   ```bash
   python3 transcribe.py "/путь" --groq
   ```

Если оба ключа лежат в `.env`, а Groq ответит 403, скрипт сам вернётся на Deepgram и
напишет об этом строкой в выводе.

## Шаг 4. Проверь установку одной командой

```bash
python3 transcribe.py --check
```

Она печатает ОС, версию Python, найден ли ffmpeg и ffprobe, путь к файлу `.env`, есть ли
прокси — и **спрашивает у сервиса, принимает ли он ключ**: это не просто «в файле что-то
вписано», а живая проверка. Возможные ответы про ключ:

- `есть, ключ принят` — всё в порядке;
- `вписан, но сервис его НЕ ПРИНЯЛ (401)` — ключ скопирован с опечаткой или обрезан.
  Вернись к шагу 3: пусть создаст новый ключ, старый уже не чини;
- `НЕ ЗАДАН` — ключ не попал в `.env`. Проверь, что правил именно тот файл, путь к нему
  печатается строкой выше;
- `вписан, проверить не смог` — нет интернета, это не про ключ.

Не иди дальше, пока в конце не появится «Готово к работе». Команда возвращает код 0,
когда всё готово, и 1, когда нет — можно опираться на это, а не только на текст.

## Шаг 5. Тестовый прогон

Попроси пользователя назвать один короткий файл (лучше до 5 минут). Запусти:

```bash
python3 transcribe.py "/путь/к/тестовому/файлу"
```

Файла под рукой нет — проверь на ссылке, это работает так же:

```bash
python3 transcribe.py "https://youtu.be/<короткое видео>"
```

Рядом с файлом должен появиться `<имя>.md` с текстом. Покажи содержимое пользователю,
спроси, устраивает ли качество.

**Файл по названному пути не находится** — не объявляй, что пользователь ошибся. Сначала
проверь, ту ли машину ты видишь (шаг 0): чаще всего это как раз тот случай. Попроси его
перетащить файл в окно терминала — путь подставится сам, и сравните.

## Шаг 6. Массовая расшифровка

Сначала план, без запуска:

```bash
python3 transcribe.py "/путь/к/папке" --plan
```

Покажи список, подтверди, что это нужные файлы. Затем настоящий запуск:

```bash
python3 transcribe.py "/путь/к/папке"
```

Для больших папок это может занять часы — предупреди и сразу договорись, кто запускает.
Если запускаешь ты, окно терминала — твоё, и «не закрывай окно» адресовано тебе: не
обрывай сессию до конца прогона. Если человек хочет заниматься своими делами и не
держать чат открытым, отдай ему команду целиком, пусть запустит у себя. Прогон
безопасно перезапускать: уже готовые файлы пропускаются.

- macOS / Linux, чтобы не держать окно: `nohup python3 transcribe.py "/путь" > /tmp/transcribe.log 2>&1 &`,
  дальше следить через `tail -20 /tmp/transcribe.log`.
- Windows: `nohup` нет — просто предупреди, чтобы не закрывал окно терминала до конца.

## Шаг 7. Скажи, как этим пользоваться дальше

Если навык лёг в папку навыков (Claude Code или Codex) — объясни главное: **больше команды
набирать не нужно**. Достаточно написать «расшифруй /путь/к/папке» — агент сам найдёт
навык и запустит скрипт.

**Но сначала скажи ему про перезапуск.** Навык, положенный в папку во время текущего
разговора, в этом же разговоре обычно ещё не подхвачен — список навыков читается при
старте сессии. Попроси закрыть этот чат и открыть новый, и только там пробовать фразу
«расшифруй …». Без этого предупреждения он напишет «расшифруй» прямо здесь, ничего не
произойдёт, и он решит, что установка не удалась.

Если это обычная папка (браузерный чат) — покажи одну команду запуска, которую он будет
копировать каждый раз.

## Расскажи про ссылки

Это вторая вещь, ради которой берут инструмент, — покажи её пользователю явно:

- Вместо пути можно дать **ссылку**, и скачивать себе ничего не надо:
  ```bash
  python3 transcribe.py "https://youtu.be/xxxxxxxx"
  python3 transcribe.py "https://disk.yandex.ru/d/xxxxxxxx"
  python3 transcribe.py "https://drive.google.com/file/d/xxxxxxxx/view"
  ```
- Понимает: YouTube, ВК Видео, Рутуб, Кинескоп, Дзен, Vimeo, Яндекс.Диск, Google Drive,
  прямая ссылка на файл.
- Скачанное скрипт убирает за собой сам — на диске остаётся только расшифровка.
- Расшифровка по ссылке ложится в текущую папку. Другое место — флаг `--out "/путь"`.
- Ссылка на **папку** Яндекс.Диска не сработает: нужна ссылка на конкретный файл. Хочет
  расшифровать целую папку с Диска — пусть скачает её себе и даст путь, так даже быстрее.

## Расскажи про разделение по спикерам

Это главное, ради чего берут Deepgram, — скажи об этом пользователю явно:

- Записи **длиннее 3 минут** размечаются сами: «Спикер 1: …», «Спикер 2: …». Созвон,
  интервью, планёрка — видно, кто что сказал.
- Короткие записи идут сплошным текстом: надиктованная мысль, метки в ней только мешают.
- Перебить решение можно флагами: `--speakers` (размечать всегда) и `--no-speakers`
  (не размечать никогда).
- Имён движок не знает, только «первый» и «второй» — кто есть кто, пользователь
  подставляет сам по смыслу реплик.

## Если что-то не работает

- **«ffmpeg не найден в PATH»** — ffmpeg не установлен или терминал не перезапущен после
  установки. Проверь `ffmpeg -version`.
- **«DEEPGRAM_API_KEY не найден»** — ключ не вписан в `.env`, или `.env` лежит не рядом с
  `transcribe.py`.
- **`HTTP 401`** — ключ неверный или скопирован с лишним пробелом. Создай новый.
- **`HTTP 403`** — это бывает только на `--groq`: Groq не обслуживает страну пользователя
  (так в РФ). Решение — убрать флаг `--groq` и работать на Deepgram. В настройки
  VPN/прокси/Clash пользователя не лезь: это его инфраструктура, и для расшифровки она
  не нужна.
- **Ссылка на YouTube не качается** — проверь, стоит ли yt-dlp (`python3 -m pip show yt-dlp`).
  Стоит, но видео не берётся — обнови: `python3 -m pip install -U yt-dlp` (ответил
`externally-managed-environment` — добавь `--break-system-packages`, см. шаг 1). YouTube
  периодически меняет защиту, свежая версия обычно уже умеет её обходить. Приватное
  видео требует cookies — файл `youtube_cookies.txt` рядом с `transcribe.py`.
- **Спикеры не разделились на явном диалоге** — проверь, что запись длиннее 3 минут или
  что стоит флаг `--speakers`. Если и так не делит — возможно, голоса записаны одним
  микрофоном и очень похожи; это предел движка, а не поломка.
- **Текст на английском вместо русского** — язык определяется автоматически; если
  стабильно путает, сообщи автору (см. README).
